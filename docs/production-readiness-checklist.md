# 上线可用框架缺口清单

## 目标定位

当前这套 `h-boot + h-boot-admin` 已经具备开发业务系统的基础框架能力，但距离“可以稳定上线使用的生产级框架”还有一段差距。

这份清单的目标不是讨论“还能做什么功能”，而是从生产上线视角，梳理当前必须补齐、建议增强、未来规划的能力缺口，方便按阶段推进。

---

## 现状判断

### 已具备的基础能力

- 前后端分离架构已成型
- 具备用户、角色、菜单、权限主链路
- 已有统一异常、日志、审计、Trace 基础
- 已有缓存基础与缓存失效机制
- 已集成工作流能力
- 已具备 Swagger、Druid、Warm-Flow UI 的环境开关
- 前端主链路已具备类型化基础

### 当前主要短板

- 测试覆盖仍然偏薄
- 前端工作流模块仍残留较多 `@ts-nocheck`
- 仍存在历史乱码、旧注释、文案不统一问题
- 工作流通知等能力仍有 `TODO`
- 前端构建产物存在较大 chunk 告警
- 生产治理能力还不完整

---

## P0：上线前必须完成

### 1. 安全基线

- 登录安全：~~补密码强度校验~~、首次登录改密、定期改密、~~账号锁定解锁~~、异地登录策略
- 认证治理：~~明确 token 过期、刷新~~、踢下线、单端/多端登录策略
- 接口防护：对登录、上传、导入、导出、流程提交等接口加限流
- 上传安全：~~限制扩展名、MIME、大小，补危险文件拦截和预留病毒扫描钩子~~
- 权限兜底：所有管理接口做后端鉴权校验，不能只依赖前端按钮权限 

### 2. 配置与环境治理

- 拆分 `dev/test/prod` 配置基线，生产环境默认关闭 Swagger、Druid、Warm-Flow UI
- 去掉生产默认弱口令、默认账号、默认上传目录隐患
- 补 `.env.example` 和生产配置说明，列出必填环境变量
- 为数据库、Redis、对象存储、短信、邮件配置健康检查

### 3. 数据库上线规范

- 引入 Flyway 或 Liquibase 管理表结构变更
- 把现有索引审计 SQL 纳入发布流程
- 区分初始化脚本、演示数据脚本、生产迁移脚本
- 明确备份、回滚、数据修复方案

### 4. 测试底线

- 后端补集成测试：登录、权限、用户/角色/菜单变更、缓存失效、异常返回
- 前端补最小回归：登录、动态路由、菜单展示、角色授权、字典页面
- 补 1 套冒烟脚本，发版前固定执行

### 5. 文案与编码治理

- 清理剩余乱码页面和共享入口文件
- 统一错误提示、按钮文案、状态文案
- 全仓检查 UTF-8，避免中文文件再被错误编码污染

---

## P1：上线后 1 到 2 个迭代完成

### 1. 前端类型彻底收敛

- 清掉剩余 `@ts-nocheck`，重点是工作流模块
- 统一 API 返回类型、分页类型、字典类型、流程实体类型
- 把高频 `any` 收敛成领域模型

### 2. 观测与运维

- 增加 Actuator 指标面板
- 接入日志检索方案，至少实现 traceId 检索闭环
- 增加慢 SQL、异常率、登录失败率、接口耗时告警
- 统一业务日志字段：`traceId`、`userId`、`bizId`、`instanceId`、`module`

### 3. 工作流补完

- 把邮件、短信、站内消息从 `TODO` 变成可配置通道
- 增加流程超时提醒、催办、撤回、转办规则配置
- 补流程操作审计查询页和导出能力

### 4. 文件中心增强

- 分片上传、断点续传、秒传去重
- 本地存储之外补 OSS / MinIO 适配层
- 文件预览、生命周期清理、访问权限控制

---

## P2：作为框架应尽快规划

### 1. 数据权限

- 支持“本人 / 本部门 / 本部门及子部门 / 全部”
- 做成注解或统一拦截，不要散落在 mapper 里手写

### 2. 多租户

- 先定方向：单库字段隔离，还是多库隔离
- 用户、角色、字典、流程、文件都要考虑租户边界

### 3. 调度与异步

- 真正接入 XXL-Job 或等价调度，不只是依赖存在
- 统一异步任务、失败重试、补偿、告警

### 4. 插件化

- 菜单、权限、路由、字典、表结构生成尽量模块化
- 为后续“可插拔业务模块”预留注册机制

---

## P3：未来趋势建议

- OpenTelemetry 标准化，避免自定义 Trace 体系长期孤岛化
- MFA / Passkey 预留，后台系统未来会越来越常见
- AI 实用化优先做：审批建议、日志诊断、SQL 分析、知识库检索
- 前端逐步走 schema-driven 表单 / 表格，减少重复页面开发成本
- 代码生成升级为“生成 CRUD + 类型 + 测试骨架 + 权限点”

---

## 上线验收门槛

- 后端编译通过，核心集成测试通过
- 前端 `type-check` 和 `build` 通过
- 权限主链路无关键 `@ts-nocheck` 残留
- 生产配置下 Swagger、Druid、Warm-Flow UI 默认不可暴露
- 登录、授权、菜单、字典、文件、流程主链路有冒烟回归
- 有发布、回滚、备份、监控、告警说明

---

## 下一步建议

建议基于这份清单，继续拆出一份“第 6 阶段实施计划”，精确到：

- 模块
- 责任范围
- 涉及文件
- 改造顺序
- 验证方式

这样后续每一项都可以直接落代码和测试，而不是停留在原则层面。
